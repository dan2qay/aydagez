# Айдагез — v0.13 (Казань)

Сайт «Айдагез» (куда сходить в Казани; запасное имя из документа `WhereToGo_Kazan.md`, домен aydagez.ru). Логотип — буква ә с волной в центре из оригинального PSD: глиф лежит в `public/brand/glyph.png` (альфа-маска, цвет задаётся CSS через `mask`), там же `logo-full.png` (знак с подписью «Әйдә ивенты») и фавиконки 64/180/512. Фон сайта кремовый из макета. Главная страница — пошаговый подбор:
что → что именно → когда → результаты, плюс строка поиска с исправлением опечаток. Данные в PostgreSQL, сервер на Node.js.

## Запуск

Нужны Node.js 20+ и Docker (для PostgreSQL). Из папки `site/`:

```bash
npm install
npm run db:up        # PostgreSQL 16 в Docker, порт 5433, том aidaem_pgdata
npm start            # http://localhost:3000
```

При первом старте сервер создаёт схему и наполняет базу: таксономия (6 категорий, 29 подкатегорий), 34 организатора, расписание на 60 дней вперёд (~390 событий). Повторные запуски ничего не дублируют; когда событий на горизонте 30+ дней становится мало, расписание достраивается.

Своя база: задайте `DATABASE_URL=postgres://user:pass@host:5432/db`. Пересобрать сид: `npm run db:reset`.

## Как устроен подбор на главной

Экраны показываются по одному, меняется только сцена, остальная страница не перерисовывается.

1. **Первый экран = поиск.** Сверху заголовок и большое поле «Кино, пробежка, квиз, английский…» с подсказками «часто ищут». Ниже блок «Или выберите интерес» с шестью категориями и кнопкой «Не знаете, что хотите?» → экран настроения. Внизу тёмный блок для организаторов «Добавьте событие» с кнопкой на форму публикации.
2. **Что именно?** Подкатегории выбранной категории (Спорт → Бег, Йога, Каток…). Кнопка «Всё из раздела» пропускает уточнение.
3. **Когда? = лента как у Luma.** Слева лента событий по дням с таймлайном (время, название, организатор, место, цена), справа закреплённый месячный календарь со счётчиками по уже сделанному выбору, а под ним карта событий выбранного дня (без выбранного дня — ближайший день с событиями). Фильтры «С кем» и «Бюджет» живут в строке поиска рядом с кнопкой «Найти» как выпадающие меню; на телефоне они же показываются над лентой. Сверху пилюли «Все дни / Сегодня / Завтра / На этой неделе / Выходные». Клик по дню в календаре оставляет только этот день, крестик возвращает все дни. На телефоне календарь открывается кнопкой.
4. **Выбрать.** Клик по карточке открывает страницу события с записью в один клик.

Строка поиска в шапке ведёт сразу к результатам: «кино», «пробежка», «познакомиться». Движок терпим к ошибкам:
нормализация и лёгкий стемминг русского, расстояние Дамерау–Левенштейна и триграммы для опечаток («прабежка» → пробежка, «шахмоты» → шахматы),
неверная раскладка («rbyj» → кино), транслит («kino»), синонимы (побегать → бег, тусовка → вечеринка), ключевые слова подкатегорий.
Если запрос исправлен, над результатами показывается «Возможно, вы имели в виду». Поисковые запросы пишутся в `search_log`.

Настроение — параметр `mood=calm|active` API: наборы подкатегорий заданы в `server/index.js`.

«Три варианта за 10 секунд» показываются над лентой всегда, когда в выдаче больше трёх событий: три карточки разных форматов и не больше одной от организатора.

## Карта

Под календарём — Яндекс Карты (JS API 2.1) с событиями выбранного дня. Ключ задаётся в `.env` (`YANDEX_MAPS_KEY=…`, см. `.env.example`; получить бесплатно в кабинете разработчика Яндекса, тариф «JavaScript API и HTTP Геокодер»).
Без ключа карта на localhost работает с предупреждением «Invalid API key», для публичного домена ключ обязателен. Если API Яндекса не загрузился за 9 секунд, автоматически включается запасная карта на Leaflet с тайлами OpenStreetMap.
Координаты площадок — `server/venues.js`, при старте сервер проставляет их событиям (`events.lat`, `events.lng`). Для событий организаторов можно передать `lat`/`lng` в `POST /api/events`.

## Экран поиска и оформление страницы события

- **Экран поиска** (`Поиск` в нижней панели, лупа в шапке, «Все фильтры» на первом экране) — обычный экран внутри приложения, навигация остаётся. Текстовый запрос плюс чипсы: категории (несколько), настроение «спокойное / активное», с кем, бюджет, когда; у каждой группы кнопка «Убрать», внизу «Сбросить всё» и кнопка «Показать N событий», счётчик обновляется на лету. «Найти» всегда ведёт к ленте по всем условиям сразу. API принимает `cat=sport,games`.
- **Оформление страницы события**, как у Luma: обложка (своё фото), галерея до 6 фото, восемь тем («Минимал», «Ночь», «Закат», «Лес», «Океан», «Конфетти», «Газета», «Неон» — свой фон, цвета, шрифт), свой цвет кнопок. Живое превью в форме создания и в кабинете («🎨 Оформить» для события или всей серии).
- Фото уменьшаются в браузере до 1600 px (JPEG) и хранятся в PostgreSQL (таблица `files`), отдаются через `GET /api/files/:id` с годовым кэшем — переживают передеплой Railway. `POST /api/upload` принимает тело `image/jpeg|png|webp` до 6 МБ. `PATCH /api/events/:id` (владелец) меняет название, описание, обложку, галерею, тему, цвет; `?series=1` — для всей серии.

## Сценарии создания (как категории товара на Авито)

Форма «Создать предложение» начинается с вопроса «Что планируете?», и дальше вопросы подстраиваются под сценарий; всё на одной странице:

| Сценарий | Примеры | Что спрашиваем | Что получается |
| --- | --- | --- | --- |
| Разовое событие | концерт, лекция, квиз | дата, время, длительность, цена, мест | 1 событие |
| Регулярное занятие | клуб по средам, йога, тренировки | дни недели, одно или несколько времён, до даты | серия |
| Сеансы | кино, театр, экскурсии | период, дни показа, сеансы в день, мест в зале | по событию на каждый сеанс |
| Прокат по часам | велосипеды, сапы, коньки, корты | часы работы, шаг брони, сколько единиц, что сдаёте | слот на каждый час, мест = единиц |
| Сеансы с группами | вейк, картинг, квесты, мастер-классы | длительность сеанса, перерыв, человек в группе, групп параллельно | слоты, мест = группа × группы |
| Свободное посещение | каток, выставка, парк | часы работы, период, вход | одна карточка на день, кнопка «Пойду» |

Внизу формы живой итог «Будет создано N событий · дней · сеансов в день · мест на сеанс». Минимум для публикации — название и место; индикатор «Заполнено на N%» подсказывает, что добавить (описание от 80/200 символов, 3+ ключевых слова, подкатегория, адрес, обложка). Ключевые слова индексируются поиском с весом подкатегории, описание — тоже.

В ленте слоты одной серии за день сворачиваются в одну карточку «10:00–19:00 · 10 сеансов · свободно на 7 из 10» с чипсами времени; на странице события — выбор сеанса с остатком мест, формулировки по сценарию («свободно 3 из 5 · велосипед на этот час», «группа до 2 · 2 группы параллельно», «открыто 10:00–22:00 · Пойду»). События хранят `kind`, `meta` (units, group_size, groups, open_from, open_to, step, unit_name) и `keywords`; `GET /api/events/:slug` отдаёт `siblings` — сеансы той же серии в тот же день.

## Кабинеты и регулярные события

- **Форма «Создать событие»** заводит разовое событие, регулярное занятие (каждый день / неделю / две недели / месяц, дни недели, «повторять до») или почасовые слоты (несколько сеансов в день, кнопка «Заполнить» сеткой с шагом 30–120 минут — для проката, кортов, тренировок). Сервер сразу создаёт все экземпляры (до 400) с общим `series_key`.
- **Кабинет организатора** `#/cabinet`: свои организаторы, статистика (ближайшие, записи, подписчики), серии с кнопкой «Отменить серию», ближайшие события со списком гостей (имя, контакт, дата записи) и отменой. Описание, контакт и сайт организатора правятся в модальном окне. Доступ — по cookie клиента, создавшего события (вход по коду — в планах).
- **Кабинет пользователя** `#/my`: ближайшие записи, прошедшие за 90 дней, подписки, интересы (сохраняются в профиле), ссылка на кабинет организатора.
- **Календарь**: тап — день; зажать и провести (на десктопе — зажать мышь и протянуть) — период от и до. При первом показе — подсказка с анимацией жеста.
- API: `POST /api/events` принимает `times[]` и `recurrence{freq, weekdays, until}`; `GET /api/cabinet`; `PATCH /api/organizers/:id`; `GET /api/events/:id/guests`; `DELETE /api/events/:id`; `DELETE /api/series/:key`. Отменённые события помечаются `cancelled` и исчезают из выдачи.

Проектный документ по кабинетам, ресурсам с почасовой сеткой и дальнейшим шагам: `docs/cabinets.md`.

## Мобильная версия

Телефон — основная точка входа, поэтому до 900px интерфейс работает как приложение: нижняя панель «Подбор / Поиск / Записи / Создать», поиск в полноэкранном листе с фильтрами и популярными запросами (кнопка-лупа в шапке и вкладка «Поиск»), фильтры открываются нижними шторками, календарь и карта показываются над лентой по кнопке «Календарь и карта», на странице события закреплена полоса с ценой и кнопкой «Записаться». Все цели для пальца не меньше 44px, поля ввода 16px (без автозума iOS), учтены safe-area выемки. Есть `manifest.webmanifest` для установки на домашний экран. Стили — `public/mobile.css`.

## Деплой на Railway

Проект `aydagez` в Railway: сервисы `Postgres` и `web`, домен https://web-production-33e48.up.railway.app.
Код заливается из папки `site/` командой `railway up --service web` (Railway CLI, вход `railway login`). Сборка Railpack/Nixpacks по `package.json`, старт `npm start`, проверка `/api/health`.
Переменные сервиса `web`: `DATABASE_URL` (ссылка на Postgres), `TZ=Europe/Moscow`, `NODE_ENV=production`; для карты добавить `YANDEX_MAPS_KEY`.
Схема и сид создаются при первом запуске автоматически. Локально сервер запускается `npm run dev` (подхватывает `.env`).

## Схема базы

`categories`, `subcategories` (с ключевыми словами), `organizers`, `events` (+ `kind`, `meta`, `keywords`, `video_url`, `promoted_until`, `erid`, `boost_terms`, `ai_tags`, `cover`, `photos`, `theme`, `accent`), `clients` (анонимный клиент по cookie `aid`, имя и контакт по желанию, интересы, тема),
`registrations` (клиент × событие), `follows` (подписки на организаторов), `digest_subscriptions`, `files` (обложки и фото, bytea + `source` с указанием библиотеки и лицензии), `settings` (секрет для QR).

Подтверждение участия и отзывы: `checkins` (событие × клиент: `guest_confirmed_at`, `organizer_confirmed_at`, `method` = qr | manual | self), `reviews` (один отзыв на событие от клиента, только при двойном подтверждении), `peer_ratings` (приватные оценки участников «встретиться снова», from → to, значение ±1).

Журнал действий для аналитики и маркетинга: `sessions` (id сессии из браузера, клиент, первый визит, referrer, landing, UTM-метки jsonb, язык, user-agent) и `client_events` (сессия, клиент, имя действия, свойства jsonb, путь, время). Пишутся с клиента пакетами через `POST /api/track` (page_view, screen, search_submit, card_click, event_view, register, checkin, review …) и с сервера по ключевым действиям; `search_log` хранит каждый запрос с фильтрами, режимом (`text` | `ai`) и сессией. Для выгрузок: `SELECT name, count(*) FROM client_events WHERE created_at > now() - interval '7 days' GROUP BY 1`.

## Личный кабинет и регистрация

Регистрация без паролей: имя, контакт, фото и тип аккаунта — «человек» или «организация» (`clients.account_type`). С `REQUIRE_PROFILE=1` записаться на событие и создавать события можно только представившись (ошибка `profile_required`, клиент показывает модалку профиля и повторяет действие). Человек собирает небольшие встречи: один сеанс в день, до 30 человек (иначе `org_required`); организация ведёт сеансы, прокат, группы, свободное посещение и продвижение. Личный кабинет `#/my`: фото, описание, тип, записи, прошедшие с отзывами, подписки, интересы, кнопка «Стать организацией».

## Организации и кабинет

Страница организации (`#/org/:slug`) устроена как карточка продавца: обложка, логотип, тип (кинотеатр, театр, прокат, курорт/парк, клуб/бар, студия, музей, спортплощадка, сообщество), рейтинг, подписчики, кнопки «Маршрут», «Написать», «Подписаться», баннер объявления (например, «Сезон открыт») и вкладки «Расписание» (лента дней, сеансы одного фильма одной строкой), «О месте», «Отзывы», «Фото». Кабинет (`#/cabinet`): Обзор со статистикой из журнала действий, Объявления (активные/на паузе/прошедшие, действия: гости, оформить, продвинуть, пауза, дублировать, отменить), Продвижение (демо-баланс, четыре продукта, кампании), Профиль, Команда (код приглашения). Подробности и сценарий рекламы для кинотеатров — в `docs/cabinets.md`.

## Панель фильтров (как у Airbnb и Авито)

В строке поиска одна кнопка «Фильтры» со счётчиком активных условий. Панель: категории (несколько сразу) и внутри каждой — виды занятий со счётчиками за выбранные даты (`server/facets.js`: бег, футбол, волейбол, бадминтон, настольный теннис, группа «Игры с мячом», скалолазание, коньки, ролики, сапы, вейкборд, велосипед, скандинавская ходьба, плавание; для других разделов — квизы, настолки, D&D, джаз, сальса, караоке, кино, театр, стендап, лекции, IT, мастер-классы, английский, татарский, знакомства…); цена с гистограммой распределения событий и двумя ползунками (`pmin`/`pmax`, «только бесплатно»); когда (быстрые периоды и календарь); с кем; время суток; атмосфера; настроение. Кнопка «Показать N событий» считает выдачу живьём (`/api/events?...&facets=1` возвращает `facets`: гистограмма цен, счётчики разделов, подкатегорий и видов — до фильтра по разделу и цене, но в выбранных датах). На телефоне та же панель встроена в экран «Поиск». Виды у событий определяются по названию, ключевым словам и тегам (`events[].acts`) и доступны как `act=football,volleyball`; ИИ-разбор фразы знает те же виды («хочу поиграть в футбол вечером» → футбол, вечер; «настольный теннис после работы» → только настольный теннис).

## Поиск: подсказки, веса, сигналы

Под строкой поиска — подсказки по префиксу (`/api/suggest`): разделы, организации с логотипами, названия событий и популярные запросы из `search_log`; стрелки и Enter. Текстовый поиск взвешивает слова по обратной частоте документов (BM25-подобно: «квиз» важнее «бар»), терпит опечатки и раскладку. В ранг добавляются клики после одинаковых запросов (`client_events`: `search_submit` → `card_click` в той же сессии), записи за 7 дней и интересы гостя. Фасеты «время суток» и «атмосфера» (шумно — музыка и танцы, тихо — поговорить) задаются выпадающими списками в шапке, на экране поиска и словами во фразе («вечером», «шумно», «тихо»).

## Ранжирование, реклама и продвижение

Выдача внутри дня сортируется по рангу (`server/rank.js`): текстовое совпадение, совпадение ИИ-тегов, рейтинг организатора, заполненность, полнота карточки. Рекламное событие (`promoted_until` в будущем, обязательно с `erid`) получает +60 и помечается бейджем «Реклама» с выделением цветом; событие с `boost_terms` поднимается на +30, когда в запросе есть одно из его слов (бейдж «Продвижение»). В «Три варианта» реклама не попадает никогда. Демо в сидах: «Мозгобойня» (реклама + boost по «квиз»), «Техно-ночь» (реклама), йога и сапы (boost).

## Фото и описание события

У каждого события есть обложка: организатор загружает свою (`POST /api/upload`), а для сидов обложки подбираются по подкатегории из свободных библиотек (`server/photos.js`: LoremFlickr → Викисклад (CC, с указанием автора и лицензии в `files.source`) → Openverse → Picsum) один раз на серию. Описание — markdown (`marked` + `DOMPurify` на клиенте): заголовки, списки, цитаты, ссылки, фото прямо в тексте (кнопка «Фото» в редакторе загружает картинку и вставляет `![](/api/files/…)`), превью «как увидят гости». Поле «Видео» принимает ссылку VK Видео, Rutube или YouTube — на странице показывается плеер.

## Отзывы и QR на входе

Отзыв можно оставить только о событии, на котором гость был, и это подтвердили обе стороны: гость на странице события открывает «Мой QR для входа» (появляется за 3 часа до начала), организатор открывает его камерой телефона (ссылка `#/checkin/:token`, работает только у владельца события) — участие подтверждено. Запасные пути: организатор отмечает «Был» в списке гостей, гость нажимает «Я был(а)» в «Моих записях». После окончания события у гостя появляется «Оставить отзыв» (оценка 1–5 и текст); рейтинг виден у организатора и в карточках. Там же «Кто был»: приватная оценка других участников «встретиться снова» — при взаимности предложим обменяться контактами.

## ИИ-поиск

Обычная строка поиска сверху тоже понимает фразы: если запрос похож на фразу (есть «хочу», «куда», «чем заняться» или 4+ слов), сервер сам включает ИИ-режим (`ai=auto`), а лента показывает, как он понял запрос; кнопка «обычный поиск» выключает его для этого запроса. Подсказки в строке — случайные примеры фраз, меняются, пока поле пустое. Блок «Спросите словами» на экране поиска: фраза гостя разбирается в признаки (с кем, настроение, улица/помещение, активность, бюджет, время), сравнивается с тегами событий, которые считаются при создании «сильной моделью» (`server/ai.js`, сейчас правила), и показывает, как понят запрос. План подключения настоящих моделей — `docs/ai-search.md`.

### Подключение настоящей модели (DeepSeek, Qwen, Ollama)

По умолчанию разбор фраз и разметка событий работают на правилах из `server/ai.js` — модель не подключена. Чтобы подключить, задайте в `.env` (локально) или в переменных сервиса на Railway любой OpenAI-совместимый API — код в `server/llm.js`:

| Переменная | Пример |
| --- | --- |
| `LLM_BASE_URL` | `https://api.deepseek.com/v1` · `https://dashscope.aliyuncs.com/compatible-mode/v1` (Qwen) · `http://localhost:11434/v1` (Ollama) |
| `LLM_API_KEY` | ключ провайдера (для Ollama любой, например `ollama`) |
| `LLM_MODEL_STRONG` | `deepseek-chat` · `qwen-plus` · `qwen2.5:14b` — размечает события при создании (один вызов на серию) |
| `LLM_MODEL_WEAK` | `deepseek-chat` · `qwen-turbo` · `qwen2.5:7b` — разбирает фразы гостей (кэш по фразе, таймаут `LLM_TIMEOUT_MS`, по умолчанию 6 с) |

Политика доверия `LLM_TRUST`: по умолчанию `gaps` — правила главнее, модель заполняет только то, чего словари не нашли (маленькие модели 0.5–3B путают дни недели и додумывают «бесплатно» или «кино»); для сильных моделей (DeepSeek, qwen-plus) ставьте `LLM_TRUST=lead`. Цена, время суток, день недели, дата («сегодня», «в выходные») и район всегда берутся из правил; догадки модели (активность, настроение, обстановка, интенсивность, с кем) не отсекают события, а только поднимают подходящие и показываются в подписи «ИИ понял» с пометкой «≈». Раздел «Детям» и фильмы (`server/seed_kids.js`): спектакли, мастер-классы, кружки, детский спорт, шоу и мультфильмы; у каждого события возрастная маркировка 0+…18+ (`events.age`), 16+ и 18+ не бывают «с детьми»; в форме создания — поля «Возраст» и «Можно с детьми». Аналитика `#/stats`, навык Алисы `/api/alice`, страницы `/e/<событие>` со schema.org, `sitemap.xml`, вход через Яндекс ID и Google, правила `#/rules` и жалобы — в `docs/growth.md`; статус идей — `docs/ideas.md`. Раздел «Развлечения» (`server/seed_fun.js`): VR и киберклубы, квесты и перформансы, батуты/верёвки/лазертаг, боулинг/бильярд/картинг, детские центры, цирк/планетарий/океанариум, антикафе, теплоходы и сити-туры — у каждого свой сценарий расписания (сеансы, слоты, свободное посещение). На главной плитки «С детьми / С друзьями / Вдвоём / Одному» и разделы раскрываются списком блоков «Все» + уточнения (как жанры в Spotify), подборка «с кем» фильтрует по `with=`. Сценарии поведения (семья → спокойно, конкретный спорт → только он, «спорт» → разные виды) лежат в `server/scenarios.js`: `npm run ai:test` проверяет правила, `npm run ai:test:full` — модель и живую выдачу, `npm run ai:dataset` выгружает JSONL для дообучения (подробнее в `docs/ai-search.md`). Если после разбора правилами слов не осталось («сегодня», «вечером», «в центре»), модель не вызывается — ей нечего добавить. Слова, которые модель дописала от себя, тоже только ранжируют: жёсткий текстовый фильтр идёт по словам гостя (`restHard`). Что происходит после подключения: `GET /api/health` показывает `llm.enabled: true`, провайдера и счётчики вызовов; в ленте под «ИИ понял» пишется «модель …» вместо «правила, без модели»; при старте сервер фоном размечает серии событий без разметки моделью (`LLM_RETAG=0` выключает). Ответ модели проверяется по схеме (только разрешённые значения), при ошибке, таймауте или пустом ответе поиск молча откатывается на правила — сайт не ломается. Для 152-ФЗ учитывайте, что текст запросов уходит провайдеру: DeepSeek и DashScope — зарубежные API, для продакшена предпочтительнее модель на своём сервере (Ollama/vLLM с Qwen) или российский провайдер с OpenAI-совместимым API.

### Qwen через Ollama на Railway

Рядом с сайтом лежит папка `../ollama-service` (`Dockerfile` на образе `ollama/ollama` и `start.sh`, который при старте докачивает модели из `OLLAMA_MODELS_PULL`, по умолчанию `qwen2.5:1.5b`). Она привязана к сервису `ollama` того же проекта Railway; разворачивание из неё:

```bash
cd ../ollama-service && railway link -p <project-id> -e production -s ollama && railway up --detach
```

Скрипт `start.sh` собирает рабочую модель `qwen-kazan` (`OLLAMA_SERVE_MODEL`) из базовой с `num_thread` = `OLLAMA_THREADS` (2) и `num_ctx` = `OLLAMA_CTX` (1536): без этого llama.cpp берёт 48 потоков на долю одного ядра и промпт обрабатывается 14 токенов/с. Веб-сервису задаются переменные `LLM_BASE_URL=http://ollama.railway.internal:11434/v1`, `LLM_API_KEY=ollama`, `LLM_MODEL_STRONG`/`LLM_MODEL_WEAK=qwen-kazan`, `LLM_WAIT_MS=2500` (сколько гость ждёт модель; дальше правила, а ответ модели ложится в кэш), `LLM_TIMEOUT_MS=120000`, `LLM_RETAG=0` (массовую разметку 0.5B не доверяем). Приватная сеть Railway — трафик за пределы проекта не выходит. На бесплатном плане Railway контейнеру достаётся около 1 ГБ памяти и том 500 МБ: туда помещается только `qwen2.5:0.5b` (модель качается в контейнер при каждом старте, около минуты), а 1.5B уже падает при загрузке (нужно ~1,1 ГБ). Для `qwen2.5:1.5b`/`3b` нужен план Hobby (до 8 ГБ на сервис) — тогда меняем `OLLAMA_MODELS_PULL` у сервиса ollama и `LLM_MODEL_*` у web. На CPU 1.5B отвечает за 3–10 с, поэтому разбор фраз кэшируется, а при таймауте работают правила; с планом на 8 ГБ памяти можно поставить `OLLAMA_MODELS_PULL="qwen2.5:3b"` и указать её в переменных веб-сервиса. Локально: `winget install Ollama.Ollama`, `ollama pull qwen2.5:3b`, переменные в `.env` (пример там же).

## Интерфейс

Шрифт Inter раздаётся со своего сервера (`/vendor/inter`), без Google Fonts. Светлая и тёмная темы (системная + переключатель).
Анимируется только меняющийся элемент: сцена шага, замена блока результатов; счётчики на днях и плитках обновляются без перерисовки.

Вход через VK ID / Яндекс ID и пароли, отправка напоминаний (email, VK, SMS), чек-ин по кодовому слову, депозит и оплата «Стола»,
импорт из Timepad и KudaGo, отчёты организатору по журналу действий, архив дайджеста `/kazan/digest/`, SEO-адреса `/kazan/segodnya/`, настоящие ИИ-модели вместо правил.
