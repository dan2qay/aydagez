# ИИ-поиск «Айдагез»: план и локальный пример

Цель: гость пишет как другу — «хочу прогуляться где-то с ребёнком, недорого» — и получает три-пять событий, которые действительно подходят. Это главный selling point для организаторов: их событие находят по смыслу, а не только по словам.

## Как это работает (двухуровневая схема)

1. **При создании события — сильная модель.** Из названия, описания, ключевых слов, места и расписания модель заполняет единую схему тегов и сохраняет её в `events.ai_tags`. Делается один раз на событие (или серию), поэтому можно позволить дорогую модель.
2. **При запросе гостя — слабая модель.** Фраза гостя разбирается в ту же схему: кто идёт, какое настроение, где (улица/помещение/вода), активность, интенсивность, бюджет, время. Дальше дешёвое сравнение тегов плюс текстовый поиск по остатку фразы. Это быстро и дёшево: тысячи запросов в день.
3. **Ранжирование.** Совпадение тегов (0–1) × 45 баллов идёт в общий ранг вместе с текстовой релевантностью, рейтингом организатора, заполненностью и полнотой карточки (`server/rank.js`). Реклама помечается и никогда не попадает в «Три варианта».

### Схема тегов (одна для события и для запроса)

```json
{
  "audience":  ["kids", "solo", "couple", "friends", "tourist", "newcomer"],
  "vibe":      ["calm", "active", "party", "smart", "romantic", "creative"],
  "setting":   ["outdoor", "indoor", "water", "food"],
  "activity":  ["walk", "run", "yoga", "skate", "bike", "water", "cinema", "theatre", "quiz", "…"],
  "intensity": "low | high",
  "price_band": "free | low | mid | high",
  "time": "morning | day | evening | night",
  "weekend": true,
  "lang": "ru | tt | en",
  "summary": "короткая человеческая подпись"
}
```

## Локальный пример (уже работает)

Сейчас обе «модели» — правила в `server/ai.js`: словари маркеров по подкатегориям и по словам. Этого достаточно, чтобы показать организаторам поведение:

- `GET /api/ai/parse?q=хочу погулять с ребёнком бесплатно` → `{ audience: ["kids"], setting: ["outdoor"], activity: ["walk"], price: "free", human: ["с детьми", "на улице", "бесплатно", "прогулка"] }`.
- `GET /api/events?q=…&ai=1` → выдача по совпадению тегов, в ответе `ai.human` — как система поняла запрос; на экране поиска блок «✨ Спросите словами», в ленте полоска «ИИ понял: с детьми · на улице · бесплатно».
- `GET /api/ai/tags/:slug` → сохранённые и пересчитанные теги события, удобно показывать организатору, «как вас видит поиск».

Теги для всех событий считаются при старте сервера (фоном) и при создании события.

## Подключение настоящих моделей (сделано, ждёт ключ)

Коннектор `server/llm.js` говорит с любым OpenAI-совместимым API (`/chat/completions`, ответ JSON). Включается переменными `LLM_BASE_URL`, `LLM_API_KEY`, `LLM_MODEL_STRONG`, `LLM_MODEL_WEAK` (см. README и `.env.example`). Проверено на локальном моке API: разбор фразы приходит от модели, лента фильтруется по её признакам, повторные фразы берутся из кэша, при недоступности модели поиск откатывается на правила.

- `parseQuerySmart(text)` — слабая модель. Системный промпт содержит схему и допустимые значения, два примера («хочу сходить познакомиться с девушкой», «хотим с подружками попеть песни») и запрет додумывать. Ответ проходит `sanitize()`: лишние значения отбрасываются, `keywords` стеммятся и идут в текстовый поиск как `rest`. Пустой ответ → правила.
- `tagEventSmart(event)` — сильная модель при создании события и фоновой разметке серий. Ответ сливается с правилами: аудитория из `with`, активности объединяются, `summary` от модели. В тегах сохраняется `model`, чтобы не размечать повторно.
- Где брать модель: DeepSeek (`deepseek-chat`), Qwen через DashScope (`qwen-turbo` для фраз, `qwen-plus` для событий) или Ollama на своём сервере (`qwen2.5:7b` / `qwen2.5:14b`) — последний вариант не отправляет данные за рубеж, что важно для 152-ФЗ. Стоимость облачных вызовов — доли копейки за фразу, разметка 100 серий — копейки.

Дальше по желанию: эмбеддинги описаний (pgvector) для «похожих событий» и для случаев, когда правила и теги молчат; обучение на журнале поиска (`search_log` с `mode='ai'`, `client_events` с `search_submit`/`card_click`/`register`) — какие ответы приводили к записи.

## Что это даёт организатору

Карточка с хорошим описанием и ключевыми словами получает полные теги и попадает в ответы на вопросы, которых организатор не предвидел: «с ребёнком в дождь», «одному вечером, спокойно», «что-то бесплатное и познавательное». Индикатор полноты карточки в форме прямо показывает, чего не хватает поиску.

## Сценарии: как «дообучаем» поиск под себя

Настоящая LoRA-дообучка Qwen требует сотен размеченных примеров и GPU; пока примеров десятки, тот же эффект даёт обучение «на лету» (few-shot) плюс правила. Всё лежит в `server/scenarios.js` — один файл, который одновременно:

1. **Тест.** `npm run ai:test` прогоняет правила по всем сценариям и падает, если разбор разошёлся с ожиданием (`npm run ai:test:full` — ещё и ответ модели, и проверки живой выдачи: «волейбол» → только волейбол, «спорт» → минимум три разных вида в первой дюжине).
2. **Примеры для модели.** На каждый запрос в системный промпт подставляются 4 ближайших сценария (по общим основам слов) плюс опорные: модель видит, что «посидеть с родственниками» — это `family + calm + food`, а «позаниматься спортом» — `activity: ["sport"]`.
3. **Датасет.** `npm run ai:dataset` выгружает `data/ai-scenarios.jsonl` в формате `messages` — его можно скормить unsloth/LLaMA-Factory, когда дойдёт до настоящей дообучки.

Правила, зашитые в разбор и ранжирование:

- **Конкретный вид — только он.** Волейбол, футбол, теннис, кино, театр, квиз и т. п. (`STRICT_ACTS`) отсекают всё остальное; общие «игры с мячом», «на воде», «спорт» уступают конкретному виду («спорт + волейбол» = волейбол, «сапы» — это сапы, а не вейк).
- **Спорт вообще — разные виды рядом.** Запрос без вида (`activity: ["sport"]`, у всех спортивных событий есть этот тег) включает чередование видов внутри дня (`diversifyByDay` в `rank.js`): бег, волейбол, скалодром, каток, а не пять пробежек подряд. То же для запросов без занятия и без слов («с семьёй в выходные»).
- **Семья — спокойно.** Родственники, родители, бабушка → `audience: family`; тег `family` получают спокойные подкатегории (прогулки, выставки, театр, кино, настолки, концерты классики), детские и площадки свободного посещения, но не шумные форматы. «Посидеть» добавляет `calm` и `food`.
- **Шум.** Если в тексте события есть и «громкие», и «тихие» маркеры («книжный клуб в библиотеке»), решает подкатегория, а не слово «клуб».

Добавить сценарий — дописать строку в `SCENARIOS` и прогнать `npm run ai:test`; если правила не справляются, сначала расширить словари в `ai.js`, и только потом полагаться на модель.
